# Crypto wave 0, batch 1: AVBlowfish and AVCAMELLIA

Route: **type**. Objective: **wrap**. No C implementation or compiled shim changes.

## Ownership and surface

- `AVBlowfish`: public `u32 p[18]` and `u32 s[4][256]`; no pointers,
  nested resources, address identity, retained aliases, or field disposers.
  `av_blowfish_alloc` uses `av_mallocz`, paired with the existing `Heap` /
  `av_free` strategy. `av_blowfish_init` also supports inline contexts
  (`libavformat/rtmpcrypt.c:rtmpe9_sig`) and reads but never retains its key.
  C accepts arbitrary positive `int` key lengths; empty keys are rejected
  before FFI. Emit inline, zeroable, copyable layouts, C-owned boxes with
  deep-copy clone, shared/exclusive handles, snapshot getters and replacement
  setters for both complete arrays.
- `AVCAMELLIA`: opaque in the public header; its C body owns only scalar
  arrays and a key-bit count. Allocation is full-sized `av_mallocz` storage,
  freed by `av_free`. No public clone/dispose primitive exists. Constructors
  accept exactly 16/24/32 bytes and expose only the initialized C owner;
  reinitialization keeps no key pointer. No private fields are exposed.
- `computeSP` rewrites global `SP` on **every** Camellia initialization.
  Constructors and reinitializers share a process-wide Rust mutex. Future
  Camellia crypt wrappers must use `lock_c_access` as well, because crypt
  reads `SP`. Raw C users must exclude simultaneous table accesses.
- No `Send`/`Sync` assertion or new public unsafe function is added. The
  ffibox ownership escape hatches are tested internally, not as `ub_unsafe`.

Wavefront queries inspected type records, symbol dependencies and lifecycle
candidates; source inspection included implementations, field touchers,
`tools/crypto_bench.c`, C tests and `rtmpe9_sig`. Findings were submitted
through `query ... --update`, including the nested substitution-table extent
that the structural record shows only as its outer dimension.

## Coverage

Coverage uses the campaign `coverage` library, Rust `-C instrument-coverage`,
private `LLVM_PROFILE_FILE` / `GCOV_PREFIX` outputs, and GCC 14 gcov. Shared
prebuild coverage files are never modified.

- Authored non-test Rust: Blowfish **36/36**, Camellia **26/26** lines.
- C: Blowfish **43/75** TU lines; allocator, initializer and ECB observer
  each have 100% executed blocks. The remaining 32 lines are the unselected
  `av_blowfish_crypt` buffer symbol, not a type/lifecycle path.
- C: Camellia **231/231** TU lines; 100% branches executed, 95.24% taken.
  Missing branch outcomes are the invalid key-bit return (safe API rejects
  before FFI) and `LR128`'s shift-at-least-128 outcome (the initializer's fixed
  shifts, reduced by 64 when needed, cannot reach it).

The `i32`-overflow key-length rejection needs a greater-than-2-GiB Rust slice
and is not allocated by these tests. Allocation failures are tested in an
exact-name subprocess so C's process-wide allocation limit cannot race with
other tests. Mutex-poison recovery has an internal unwind regression.
